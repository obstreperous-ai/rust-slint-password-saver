9. RECOMMENDATION
================================================================================

9.1 RECOMMENDED APPROACH: Keep MIT + Use Slint Royalty-Free License 2.0
------------------------------------------------------------------------

The project should:

  1. USE SLINT UNDER THE SLINT ROYALTY-FREE LICENSE 2.0
     This avoids the copyleft obligations of GPL-3.0 and allows the project
     to remain MIT-licensed for its own code.

  2. KEEP THE MIT LICENSE for the project's own source code.
     MIT is maximally permissive, encouraging adoption and contribution.
     All non-Slint dependencies are MIT-compatible.

  3. SATISFY THE SLINT ATTRIBUTION REQUIREMENT by doing one of:
     (a) Adding the AboutSlint widget to the application's UI (recommended
         as it is self-contained within the application), OR
     (b) Adding the Slint attribution badge to the project's README or
         GitHub releases page.

  4. ADD A LICENSE CLARIFICATION to the README and/or a NOTICE file:
     - State that the project's own code is MIT-licensed.
     - State that the Slint framework components are used under the
       Slint Royalty-Free Desktop, Mobile, and Web Applications License,
       Version 2.0.
     - Provide a link to the Slint license text.

9.2 RATIONALE
--------------

  - The MIT license maximizes downstream adoption and is the standard for
    Rust ecosystem libraries and applications.
  - The Slint Royalty-Free License 2.0 is specifically designed for desktop
    applications like this password manager, and imposes only a lightweight
    attribution requirement.
  - Switching to GPL-3.0 would significantly restrict downstream use
    (no proprietary forks, viral copyleft obligations) which is undesirable
    for a password manager that users may want to customize privately.
  - The project does NOT target embedded systems, so the embedded-system
    restriction of the Royalty-Free license does not apply.

9.3 ALTERNATIVE: Switch to GPL-3.0
------------------------------------

If the project maintainers prefer to use only OSI-approved licenses and
embrace copyleft principles, the project should:

  1. Change the LICENSE file to GPL-3.0-only.
  2. Update Cargo.toml: license = "GPL-3.0-only"
  3. Add GPL-3.0 headers to all source files.
  4. Update README to reflect the license change.

This is a valid approach but reduces the project's appeal to users who
need permissive licensing for their own downstream integrations.

9.4 NOT RECOMMENDED: Dual License (MIT OR GPL-3.0)
-----------------------------------------------------

While dual-licensing is sometimes used in the Rust ecosystem, it would
create confusion here because:
  - The Slint components can only be GPL-3.0 or Slint Royalty-Free, not MIT.
  - Downstream users who choose MIT would still need to comply with the
    Slint license separately.
  - This adds complexity without meaningful benefit.
